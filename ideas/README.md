# Ideas

The author's raw post ideas, one file per idea, exactly as given. These are not posts.

| Folder | What's in it |
|---|---|
| `open/` | Not used yet. `generate-content` and `content-plan` pick from here. |
| `used/` | Ideas that became a post, with a link to it. Consult for follow-ups with new evidence. Keep the original; create a separate linked brief. |
| `files/` | Screenshots, photos and transcripts that come with an idea. |

Examples: `examples/ideas/open/` has two raw ideas, and `examples/ideas/used/` two ideas that became the posts in `examples/outputs/posts/published/`. `examples/ideas/used/2026-10-21-character-ai-bankruptcy.md` keeps the whole trail: the raw notes, the brief, every fact with its source, the hooks and the check.

## Rules

- Save the author's words verbatim, typos included. No polishing, no merging, no drafting.
- An idea is not a request to write. Save it and stop, unless the author asks for the post.
- Add one tag line under the idea, marked as a guess: pillar, category, the proof it has or needs.
- When a post is drafted from an idea, move the file to `used/` and add `Used: YYYY-MM-DD → <post file>`.
- Dropped ideas go to `used/` with `Dropped: <reason>`. Nothing gets deleted.
- The author can add an idea directly: a new file in `open/` with a title line and the text. The tag line gets added later.

## File format

File name: `YYYY-MM-DD-short-slug.md`

    # <short title, in the author's words>
    Added: YYYY-MM-DD

    <the author's words, verbatim>

    Files: files/<name>  (if any)
    Tags (guess): pillar N · growth | authority | personal | conversion · proof: <what makes it real, or "needs: ...">
