# X post

Paths are relative to the workspace root. Apply `linkedin-post` steps 1–2 with X samples and the shared rules in `CLAUDE.md`.

## Pick the points

Write one post per point an X reader can use without the LinkedIn post. A post with one point gets one post. Write the X posts separately from the Threads posts: on X a reply counts most, so the X version can invite an answer or an argument; the Threads version carries the personal side. They can share a sentence, but not as the rule: never reword the author's line only to make the two differ.
Write a set when the post fits the X audience in `strategy/positioning.md`. Personal posts usually keep one.
Each post states its point in the first line or two, without suspense or a generic promise.
Each post triggers one feeling from `references/psychology.md` in its first line, usually the one the LinkedIn post opens with.
Lead with the author's view or experience, not an explanation: on X opinions reach people who don't know the author, while teaching stays on LinkedIn (a creator's X and Threads playbook, `references/reach.md`). Pick points a stranger in their audience cares about, about their own work, fears or hopes, not inside talk only their circle would get.
The author's own question works well on X, because replies count most there. Never add one they don't have, and keep it specific to the reader: broad questions bring views, not followers who stay.
When the reader is a clear group (founders, engineers, people who write at work, people writing in a second language), name it in the first words (Group callout in `references/formats.md`). A one-line opinion the author holds, a Fear line or a Pick a side post can be the whole post (`references/formats.md`).
No sentence appears in two posts of the set: X limits recommendations for copy-pasted posts.
Use a short thread only when the material is a real sequence of steps. Use a long post only when the author requests it and their account supports it.

## Write

Use at most 280 characters per post. A link counts as 23.
Preserve the author's wording. Remove context the reader can infer, but retain evidence and necessary qualifications. To fit the limit, cut a clause or a repeated detail, not the detail that makes the post theirs.
Use a line per step only for a real sequence. Avoid hashtags and thread markers unless their samples support them.
No first reply with links or sources. Leave the link out; put one in the post only when the author asks.
Optional tests: "unpopular opinion:" can open a belief the author holds that really splits people; an either/or question is fine when the author has their own answer and gives it in the replies. No engagement-bait posts ("what are you building?", "drop your link").
Product mentions follow `strategy/product.md`.

## Visuals

Use `strategy/visuals.md`: an artifact, diagram or comparison can carry details the text cannot fit.
Put the post file's visual on the one post it supports. Use up to four images, each with alt text. Check that code and labels remain readable in the selected crop.

## Finish

Run `humanizer`, then `voice-check`, once.
Save under `## X` as `### Post 1`, `### Post 2` and so on, with each post's visual below it. A set replaces an earlier single post.
Show each post with its character count and visual or asset link. Count URLs using the platform's composer when exact limits matter.
Tell the author to post a set at least two days apart, mixed with other topics. X's published ranking code (github.com/xai-org/x-algorithm, checked 2026-10-13) ranks only posts from the last 48 hours, and in one feed each extra post by the same author scores lower.
Remind the author to answer replies in the first hours and to follow back people in their niche who engage: X counts a likely reply at 5.0 and a like at 0.66, and the reply at 20 when the two accounts follow each other (same repository, checked 2026-10-17).
