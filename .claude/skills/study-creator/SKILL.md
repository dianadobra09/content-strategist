# Study a creator

Paths are relative to the workspace root. The author's own material remains the source of their voice and opinions.

## Collect

Use supplied posts, saved studies or an available authorized read-only feed. Ask for material only when access is unavailable.
If the purpose is unclear, ask what the author wants to learn. Do not repeat a question already answered in context.
Aim for a recent sample of roughly 10–20 original posts. State the actual size and selection limits.
Keep selected best examples separate from the recent sample; do not calculate a typical result from best posts alone.
Record capture date, post dates, URLs, visible counts, partnerships and excluded reposts.
Missing counts are unknown. Note that comments can include the author's own replies.
Inspect visuals before describing their contents; distinguish an attachment count from an inspected image.

## Analyze

Look at the intended reader, useful promise, opening, body structure, evidence, ending, visual, recurring subjects and cadence.
Use strong examples and counterexamples. Separate observed engagement from results claimed inside a post.
Do not rank creators as winners from unmatched audiences and post ages. Note known collaboration between creators.
Treat reach patterns as hypotheses, not algorithm rules. Verify external facts separately before using them in the author's posts.

## Compare with the workspace

Read the relevant skills, formats, reach notes and the author's available posts.
Identify what is already covered, what is missing and which active instructions conflict with the finding.
Name the exact file and section for each proposed change, with a reason and a small test.
Ready drafts show topic coverage, not measured performance. Other creators never establish the author's beliefs or preferred voice.

## Save and report

Save `references/creators/<platform>-<handle>.md` with evidence limits, links, useful structures and the comparison.
Use short excerpts only when needed. Add a format only when it differs usefully from the existing set.
Keep self-reported reach claims attributed in `references/reach.md`. Do not turn them into mandatory selection rules.
Apply skill changes when requested; a study alone does not authorize rewriting approved posts or reordering the queue.
Report the main lessons and proposed changes concisely. Add a creator to the voice guide's quality bar only if the author admires their craft.
