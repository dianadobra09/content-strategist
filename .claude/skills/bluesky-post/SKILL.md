# Bluesky post

Paths are relative to the workspace root. Apply `linkedin-post` steps 1–2 with Bluesky samples and the shared rules in `CLAUDE.md`.
If Bluesky samples are absent, use the author's own notes and stated voice preferences.

Follow the Bluesky focus in `strategy/positioning.md` (by default: engineering, limits, privacy, communication and practical work).
Write one post per point a Bluesky reader can use without the LinkedIn post. A post with one point gets one post. Points outside the focus get no post; AI-tooling posts go to LinkedIn and X.
No sentence appears in two posts of the set, so each one tells a follower something new.
Explain what happened or what the author learned, with one feeling from `references/psychology.md` in the first line. Do not add promotional language or audience stereotypes; the product can be named once, plainly, where it fits. A one-line opinion the author holds, or a Fear line, can be the whole post (`CLAUDE.md` rule 1).
Keep the author's full sentences. Use a question only when it is theirs or they actually want an answer.
Product mentions follow `strategy/product.md`. A post about the product still needs a useful build note.

Use at most 300 characters per post. A thread is appropriate only when each part supplies a distinct useful detail in a real sequence.
Links can sit in the post, never in a first reply. Use no hashtags unless a chosen custom feed requires one.
Adapt each point to this audience instead of compressing every detail from LinkedIn. The Threads or X posts in the file are often the closest shape.

Use `strategy/visuals.md` for photos, artifacts and factual technical visuals. Put the post file's visual on the one post it supports. Use up to four images, with alt text on each.
Run `humanizer`, then `voice-check`, once.
Save under `## Bluesky` as `### Post 1`, `### Post 2` and so on, with each post's visual below it. A set replaces an earlier single post.
Show each post with its character count and visual or asset link. Check the composer when Unicode or links make the count uncertain. Suggest mixing a set with other topics rather than posting it in a row.
